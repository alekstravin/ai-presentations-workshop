Подключи GigaChat API к УЖЕ установленному Hermes на моём VPS и настрой постоянный автозапуск Gpt2Giga. Выполни работу и проверки, а не только напиши инструкцию.

Исходные данные:
- Существующий SSH alias/пользователь@сервер: <указать>.
- Серверный пользователь и профиль Hermes: <определи по действующей службе; не предполагай root>.
- Служба Hermes: <определи фактическое имя>.
- Модель: <точный доступный ID либо подбери из доступных с поддержкой tools и достаточным реальным контекстом>.
- Scope GigaChat: <значение из кабинета; для физлица обычно GIGACHAT_API_PERS>.
- Authorization key: предоставлю скрытым вводом либо через согласованный приватный файл/хранилище.
Не проси ключ обычным сообщением, не печатай его, не помещай в аргументы команд, историю, Git или итоговый отчёт. Если скрытый ввод недоступен, подготовь приватный файл с правами 600 и дай мне заполнить его самостоятельно. Не выдумывай реквизиты и не продолжай зависимые проверки без них.

1. Изучи актуальные официальные инструкции Сбера, Hermes и Gpt2Giga; проверь версию пакета и --help. Документация текущей ветки может отличаться от опубликованного стабильного пакета. Сначала без изменений обследуй ОС, пользователя/HOME, профиль Hermes, unit, текущего провайдера и модель, порты, ресурсы и действующий Gpt2Giga. Не выводи секреты при чтении конфигураций. Запиши исходную работоспособность Hermes и других сервисов. Не создавай второй прокси при наличии подходящего рабочего.

2. Подготовь приватные резервные копии только меняемых файлов и план отката. Не переустанавливай VPS, не меняй HTTPS/nip.io, SSH, reverse proxy, firewall других служб, Docker-сети и чужие .env. Не перезагружай VPS. Не обновляй все пакеты системы. При конфликте прав/портов выбери свободный loopback-порт и согласованно используй его; не останавливай чужой процесс.

3. Установи официальный опубликованный gpt2giga в отдельное Python venv, например /home/hermes/gpt2giga/.venv, от подходящего непривилегированного пользователя. Проверь поддерживаемую версию Python. Зафиксируй фактически установленную версию и зависимости для воспроизводимости. Не выдавай агенту sudo или Docker socket. По умолчанию не устанавливай непроверенную ветку main вместо стабильного выпуска.

4. Создай приватный .env в каталоге прокси. Используй параметры, поддерживаемые установленной версией:
GPT2GIGA_HOST=127.0.0.1
GPT2GIGA_PORT=<свободный порт; пример 8090>
GPT2GIGA_ENABLE_API_KEY_AUTH=True
GPT2GIGA_API_KEY=<отдельный случайный секрет не менее 32 символов>
GIGACHAT_CREDENTIALS=<Authorization key>
GIGACHAT_SCOPE=<scope из кабинета>
GIGACHAT_VERIFY_SSL_CERTS=True
При необходимости добавь поддерживаемый PROD-режим и актуальный адрес GigaChat по документации. Не используй временный access_token как постоянный ключ. Пусть SDK получает и обновляет токены. Ключ прокси и Authorization key Сбера — разные секреты. При ошибке CA установи проверенную цепочку по официальной инструкции Сбера и укажи поддерживаемый путь к bundle; не отключай TLS-проверку. Порт прокси не публикуй и отдельный HTTPS-сайт для него не создавай.

5. Создай отдельный systemd unit для Gpt2Giga с правильными User, HOME, WorkingDirectory, PATH, EnvironmentFile и абсолютным ExecStart из venv. Учитывай, что .env должен читаться выбранным пользователем и синтаксис быть совместимым с systemd. Restart=on-failure, разумная задержка, UMask=0077, автозапуск. Не выводи Environment или содержимое секретных файлов в отчёт. Проверь unit и запусти службу; заверши ручной процесс прокси, если именно ты его запустил на этом порту. Не оставляй два конкурирующих экземпляра.

6. В действующем нужном профиле Hermes настрой Custom/OpenAI-compatible provider: base_url http://127.0.0.1:<порт>/v1, API key — отдельный ключ ПРОКСИ, model — точный доступный ID. Не вставляй сюда Authorization key Сбера. Сохрани остальные настройки, инструменты, MCP, историю и данные профиля. Не меняй модель во всех профилях. Проверь поддержку tools и достаточное реальное окно; не завышай context_length ради обхода проверки. Перезапусти только нужный Hermes backend после изменений и начни новый сеанс.

7. Проведи полный цикл проверок:
- Gpt2Giga active/enabled, процесс от непривилегированного пользователя, порт только loopback;
- без ключа прокси защищённый endpoint отклоняет запрос, с ключом доступен каталог моделей;
- обычная генерация через прокси и затем через нужный профиль Hermes;
- тест функции add_numbers(7,11): реальный tool call, возврат 18 инструментом, принятие результата моделью и финальный ответ;
- реальное создание/чтение hello.txt в отдельной тестовой папке пользователя Hermes (не чужих данных);
- restart только Gpt2Giga, затем повторный ответ из Hermes; выход из установочного SSH не останавливает службы;
- подтверждение механизма обновления токена; если не дождался истечения токена, прямо отметь, что длительная проверка обновления не проведена;
- прежний HTTPS-вход Hermes, WebSocket и остальные исходные сервисы продолжают работать.
HTTP 200 от /models не является доказательством работающего агента. При отказе tool-calling не объявляй подключение полностью готовым и не переходи молча на другую модель. Уточни ошибку, доступность и квоту выбранной модели.

8. Если что-то сломалось, восстанови только свои изменения согласно плану отката и проверь прежнюю конфигурацию. В итоге укажи: установленную версию Gpt2Giga, фактический ID модели/scope без секретов, профиль Hermes, loopback URL и порт, имя unit и пути файлов, команды status/restart/journalctl, что проверено и что осталось. Не выводи логины/адреса в публичные материалы. Не утверждай, что выполнен тест с телефона или полная перезагрузка VPS, если этого не было.

Действуй автономно в этих пределах. Остановись только при отсутствии необходимых прав/секретов, интерактивной авторизации или риске для других сервисов. Не считай ожидание ответа разрешением на рискованный шаг.
